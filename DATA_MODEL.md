# DATA_MODEL.md

Проект стартует в локальном режиме. Записи живут в браузере текущего устройства.

## Универсальная запись

- `id` — уникальный идентификатор.
- `record_type` — тип: заявка, результат квиза, клиент или задача.
- `payload` — полезные поля конкретной записи.
- `status` — текущий этап.
- `created_at` — дата создания.
- `updated_at` — дата изменения.
- `archived_at` — дата архивации.

## Заявка агентства

Запись с `record_type: lead` содержит имя, телефон, дату события, город, возраст ребёнка при необходимости, комментарий, выбранные услуги и известную часть предварительной стоимости. Снимок выбранной услуги сохраняет `id`, название, категорию, длительность, изображение, цену и единицу цены.

Корзина до отправки хранит только идентификаторы услуг в `localStorage`.

## Владелец данных

До подключения базы локальные записи видит только этот браузер. Интерфейс прямо сообщает об этом после отправки.

После подключения Supabase записи принадлежат `workspace_id`. Читать и менять их может участник рабочей области. Публичная форма может только создать ограниченный тип записи.

## Не храним

- платёжные данные карты;
- пароли;
- паспортные данные;
- секретные ключи;
- лишние личные сведения «на будущее».
